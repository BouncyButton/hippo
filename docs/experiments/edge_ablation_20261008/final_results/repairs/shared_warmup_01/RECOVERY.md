# Recovery after job 690510

The job stopped in reporting after its ninth training run completed. Eight completed runs reproduced the baseline's five-epoch Dice-only prefix exactly. `probability_1and3mm_pairs_outer` differed before any constraints were active: maximum absolute prefix validation Dice difference 0.00034124872058444167 (0.0341 percentage points), and band coefficient 0.002145659159035607 versus 0.0021464975081461886. It remains excluded from comparisons until rerun from an accepted prefix. Its original results are preserved, independent of whether its final Dice was better or worse.

All 142 frozen payload files and the dataset SHA-256 still match. The training code computes exactly the same Dice-only objective during all five prefix epochs, without constructing branch-specific targets. It seeds RNGs and requests deterministic cuDNN convolutions, but does not enable deterministic algorithms for all CUDA operations. Therefore its assumption that independently recomputed GPU prefixes would always match was stronger than its reproducibility controls. The observed small early numerical drift is consistent with CUDA nondeterminism; the particular kernel has not been isolated. See [PyTorch reproducibility documentation](https://github.com/pytorch/pytorch/blob/main/docs/source/notes/randomness.md).

The recovery wrapper enforces a common prefix by checkpoint restoration. It generates a prefix using the unchanged frozen trainer, requires the existing warmup and calibration checks to pass against the baseline, and preserves the complete model, optimizer, scheduler, RNG and case-order state. It allows up to three prefix probes, then stops if none match. Acceptance depends only on warmup and calibration, never final experiment performance. Remaining arms restore that one state before epoch 6. No tolerance, loss, learning rate, dataset, split, seed, stopping rule or frozen source is changed.

Eight accepted runs are retained and verified by their original artifact hashes. The unmatched ninth trial is moved to `repairs/shared_warmup_01/excluded/` after a prefix has passed verification. It is rerun, followed by the eleven unstarted arms. The frozen original report still checks every completed run. Calibration is checked after epoch 6 so a mismatch stops early. A recovery status and audit record preserve the original failure, excluded run and shared-checkpoint hashes. The original submission receipt is retained; recovery has its own scheduler receipt.

Regression tests reject the observed drift at the original tolerances, reject active constraints in the prefix, preserve artifact integrity, and show that restoring the common state reproduces uninterrupted training exactly even after deliberately changing initialization and RNG state. Existing campaign tests also run. GPU verification is required before the remaining comparisons are accepted.

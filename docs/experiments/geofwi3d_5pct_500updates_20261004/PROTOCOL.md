# GeoFWI3D 5%: exploratory 500-update baseline

The user requested a 5% run with best validation Dice in the 70% range. The completed 5% baseline (job 682953) reached 0.7374 at update 500, 0.7846 at update 600, and an eventual best of 0.8327 at update 2400. We therefore choose a fresh **500-update pilot** based on that observed learning curve. This budget choice is validation-informed and must be disclosed when using the experiment in the thesis. The earlier 0.8327 result remains the original, longer-budget baseline.

The new model is trained from scratch on the same 19 labelled salt-containing training volumes, with the same 96 complete native 96³ validation volumes, split seed 0, model seed 0, SwinUNETR architecture, Dice+CE loss, augmentation and numerical precision. The 100-update warmup and original 5,000-update cosine learning-rate horizon are preserved; the optimizer simply stops after update 500. The shorter cap does not compress the learning-rate schedule. This makes the run a replication of the first 500 updates of the earlier baseline, subject to numerical reproducibility.

Validation occurs at updates 100, 200, 300, 400 and 500. The exact highest mean foreground hard Dice across these checks selects the checkpoint. Minimum training duration equals the 500-update cap; the ten-check early-stopping patience cannot trigger in this five-check pilot. There is no stopping rule based on reaching a desired Dice range. The actual best score will be reported even if it falls outside 0.70–0.80; this protocol does not authorize retuning or repeated runs until a requested score appears.

This is baseline only, with no test set or new annotations. For a later constraint comparison, use the same 500-update cap, learning-rate horizon, seed policy, validation opportunities and training subset. Any measured gain would be evidence at this exploratory budget, not a replacement for the earlier longer-budget result or independent confirmation across seeds.

WHAT YOU WILL SEE
Startup prints its phase before slow work. It lists actual run/recovery folders once, rather than
checking hundreds of absent paths. Each existing archive is copied once to a session-local SSD cache;
the original verifier checks its hashes, sizes, readability, identity, source binding and cleanup.
Results and matched baseline metadata are then read from that verified cache. The cache is verified
anew each session and never replaces a durable archive. Completed Drive archives are not rewritten.

A heartbeat every 30 seconds distinguishes progress from still waiting. It shows startup archive
checked/verified counts, completed count, run IDs, worker count, successful and charged updates,
GPU utilization, VRAM, CPU load and RAM available. GPU VRAM is capacity, not GPU activity.
Each worker reports loading, initialization, calibration, training, evaluation, checkpointing,
Drive ledger wait and recovery upload. Timing and memory peaks are saved with run metadata.
Wall-clock timings overlap; they are not synchronized CUDA kernel timings.

Live status is local, independent of Drive:

 /content/hippo_adni_bundle/parallel_status/<session>/timing.jsonl
 /content/hippo_adni_bundle/parallel_status/<run-id>.json
Setup/preflight status: /content/hippo_adni_setup_status.json
Notebook logs: /content/hippo_adni_run.log and /content/hippo_adni_preflight.log
Session telemetry is copied under results_noaug_v1/parallel/<session>/ at clean completion.
A hard VM loss may lose local telemetry; the original durable accounting/recovery still governs resume.

CONCURRENCY
Unknown model/condition memory requirements are measured by that condition's first pending real run,
which runs alone through training and evaluation. No additional experiment is used.
With known full-run peaks, low GPU utilization, CPU/RAM/VRAM/storage headroom and a stable window of
completed-update throughput, one further pending scientific run may be admitted provisionally.
A further increase requires a measured gain of at least 5%; otherwise future launches reduce.
Running work is not cancelled to tune throughput. Short runs or insufficient measurements can keep
concurrency at one. The worker ceiling derives from available CPU cores; each trainer keeps two threads.
No data, annotation, model or gradient cache changes were added to the scientific implementation.

STOP AND RESUME
Interrupt the run cell once and wait for all workers to finish verified recovery uploads. Do not
restart/delete the VM while uploads are pending. Completed runs are verified and skipped; interrupted
work is audited and scheduled before fresh work. Existing STOP files remain in effect until you
intentionally resume. A worker/archive failure stops new launches and drains the other workers.
A checkpoint behind the durable charge ledger blocks resumption instead of silently repeating compute.
Local locks and a persistent Drive ownership marker reject visible competing controllers. Drive FUSE
is not a distributed lock service: never start controllers simultaneously from separate VMs. After
an unclean VM loss a leftover .adni_controller_lock requires ownership/recovery inspection; it has
no automatic expiry. Do not remove it merely to make a run proceed.
